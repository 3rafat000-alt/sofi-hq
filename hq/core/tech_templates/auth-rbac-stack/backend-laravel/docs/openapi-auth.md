# The Authentication Contract — OpenAPI 3.1 (`/api/v1/auth`)

> **Status:** the official contract of phase 2 (the authentication & permissions engine) — the frontend (06) and mobile (07) rooms build on it exclusively.
> **Source:** generated by hand from the actual code (`AuthController` + `FormRequests` + `ApiResponse`) with a literal match to the envelope in `hq/core/standards/api-envelope.md#envelope-v1`.

## Quick Summary

| Route | Method | Protection | Success | Possible Errors |
|--------|---------|---------|--------|--------------|
| `/api/v1/register` | POST | public + throttle 10/min | **201** | 404, 422, 429 |
| `/api/v1/login` | POST | public + throttle 10/min | **200** | 401, 403 (suspended/banned), 422, 429 |
| `/api/v1/logout` | POST | `auth:sanctum` | **200** | 401 |
| `/api/v1/me` | GET | `auth:sanctum` | **200** | 401 |
| `/api/v1/users/{user}/role` | PUT | `auth:sanctum` + `role:super-admin,manager` | **200** | 401, 403, 404, 422 |

**Authentication:** after obtaining the token, send the header `Authorization: Bearer <token>` on every protected call.

## Full Specification

```yaml
openapi: 3.1.0
info:
  title: Auth & RBAC API
  version: "1.0"
  description: >
    Every response — success or failure — is wrapped in Envelope v1 with exactly
    four root keys: success | data | error | meta. Error codes are fixed:
    VALIDATION_FAILED(422), UNAUTHENTICATED(401), FORBIDDEN(403),
    NOT_FOUND(404), RATE_LIMITED(429).
servers:
  - url: /api/v1
tags:
  - name: Auth
    description: First-party authentication (SPA/mobile via Sanctum tokens)

components:
  securitySchemes:
    bearerAuth:
      type: http
      scheme: bearer
      bearerFormat: Sanctum personal access token

  schemas:
    Meta:
      type: object
      required: [timestamp, api_version]
      properties:
        timestamp: { type: string, example: "2026-08-23T12:00:00Z" }
        api_version: { type: string, const: "v1" }

    RolePayload:
      type: object
      nullable: true
      required: [id, name, display_name]
      properties:
        id: { type: integer }
        name: { type: string, enum: [super-admin, manager, user] }
        display_name: { type: string }

    UserPayload:
      type: object
      required: [id, name, email, status, created_at, role, permissions]
      properties:
        id: { type: integer }
        name: { type: string }
        email: { type: string, format: email }
        status: { type: string, enum: [active, suspended, banned] }
        created_at: { type: string, format: date-time }
        role: { $ref: "#/components/schemas/RolePayload" }
        permissions:
          type: array
          items: { type: string }
          description: Flat machine-name strings (e.g. users.create) for UI gating.

    AuthData:
      type: object
      required: [user, token, token_type]
      properties:
        user: { $ref: "#/components/schemas/UserPayload" }
        token: { type: string, description: Sanctum plaintext token }
        token_type: { type: string, const: Bearer }

    MeData:
      type: object
      required: [user]
      properties:
        user: { $ref: "#/components/schemas/UserPayload" }

    MessageData:
      type: object
      required: [message_ar, message_en]
      properties:
        message_ar: { type: string }
        message_en: { type: string }

    ErrorBody:
      type: object
      required: [code, message_ar, message_en, fields]
      properties:
        code:
          type: string
          enum: [VALIDATION_FAILED, UNAUTHENTICATED, FORBIDDEN, NOT_FOUND, CONFLICT, RATE_LIMITED, SERVER_ERROR]
        message_ar: { type: string }
        message_en: { type: string }
        fields:
          type: object
          nullable: true
          additionalProperties:
            type: array
            items: { type: string }
          description: Field→Arabic messages map; null unless validation failed.

    EnvelopeError:
      type: object
      required: [success, data, error, meta]
      properties:
        success: { type: boolean, const: false }
        data: { type: "null" }
        error: { $ref: "#/components/schemas/ErrorBody" }
        meta: { $ref: "#/components/schemas/Meta" }

    EnvelopeAuth:
      type: object
      required: [success, data, error, meta]
      properties:
        success: { type: boolean, const: true }
        data: { $ref: "#/components/schemas/AuthData" }
        error: { type: "null" }
        meta: { $ref: "#/components/schemas/Meta" }

    EnvelopeMe:
      type: object
      required: [success, data, error, meta]
      properties:
        success: { type: boolean, const: true }
        data: { $ref: "#/components/schemas/MeData" }
        error: { type: "null" }
        meta: { $ref: "#/components/schemas/Meta" }

    EnvelopeMessage:
      type: object
      required: [success, data, error, meta]
      properties:
        success: { type: boolean, const: true }
        data: { $ref: "#/components/schemas/MessageData" }
        error: { type: "null" }
        meta: { $ref: "#/components/schemas/Meta" }

paths:
  /register:
    post:
      tags: [Auth]
      summary: Create an account, assign the default role "user", return a token
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required: [name, email, password, password_confirmation]
              properties:
                name: { type: string, maxLength: 255 }
                email: { type: string, format: email, maxLength: 255, description: Lowercased; unique per users table }
                password: { type: string, minLength: 8 }
                password_confirmation: { type: string, minLength: 8 }
      responses:
        "201":
          description: Account created
          content:
            application/json:
              schema: { $ref: "#/components/schemas/EnvelopeAuth" }
        "404":
          description: Default role not provisioned (system misconfiguration)
          content:
            application/json:
              schema: { $ref: "#/components/schemas/EnvelopeError" }
        "422":
          description: Validation failed — Arabic messages in error.fields
          content:
            application/json:
              schema: { $ref: "#/components/schemas/EnvelopeError" }
        "429":
          description: Rate limit exceeded (10 requests/minute)
          content:
            application/json:
              schema: { $ref: "#/components/schemas/EnvelopeError" }

  /login:
    post:
      tags: [Auth]
      summary: Verify credentials and issue a token
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required: [email, password]
              properties:
                email: { type: string, format: email }
                password: { type: string, description: Plain input — verified server-side against stored hash }
      responses:
        "200":
          description: Authenticated
          content:
            application/json:
              schema: { $ref: "#/components/schemas/EnvelopeAuth" }
        "401":
          description: Invalid credentials (UNAUTHENTICATED)
          content:
            application/json:
              schema: { $ref: "#/components/schemas/EnvelopeError" }
        "403":
          description: Account suspended or banned (FORBIDDEN — message distinguishes)
          content:
            application/json:
              schema: { $ref: "#/components/schemas/EnvelopeError" }
        "422":
          description: Validation failed
          content:
            application/json:
              schema: { $ref: "#/components/schemas/EnvelopeError" }
        "429":
          description: Rate limit exceeded
          content:
            application/json:
              schema: { $ref: "#/components/schemas/EnvelopeError" }

  /logout:
    post:
      tags: [Auth]
      summary: Revoke the current access token only
      security: [{ bearerAuth: [] }]
      responses:
        "200":
          description: Logged out
          content:
            application/json:
              schema: { $ref: "#/components/schemas/EnvelopeMessage" }
        "401":
          description: Missing/expired token
          content:
            application/json:
              schema: { $ref: "#/components/schemas/EnvelopeError" }

  /me:
    get:
      tags: [Auth]
      summary: Current identity with role + permissions (Eager Loaded)
      security: [{ bearerAuth: [] }]
      responses:
        "200":
          description: Current user
          content:
            application/json:
              schema: { $ref: "#/components/schemas/EnvelopeMe" }
        "401":
          description: Missing/expired token
          content:
            application/json:
              schema: { $ref: "#/components/schemas/EnvelopeError" }

  /users/{user}/role:
    put:
      tags: [Auth]
      summary: Change another user's role (super-admin | manager only)
      description: >
        Escalation guard: non-super-admin callers cannot grant the super-admin
        role nor modify super-admin accounts (403).
      security: [{ bearerAuth: [] }]
      parameters:
        - name: user
          in: path
          required: true
          schema: { type: integer }
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required: [role]
              properties:
                role: { type: string, enum: [super-admin, manager, user], description: Must exist in roles table }
      responses:
        "200":
          description: Role changed — updated user returned
          content:
            application/json:
              schema: { $ref: "#/components/schemas/EnvelopeMe" }
        "403":
          description: Caller lacks the role, account inactive, or escalation blocked
          content:
            application/json:
              schema: { $ref: "#/components/schemas/EnvelopeError" }
        "404":
          description: Target user or requested role not found
          content:
            application/json:
              schema: { $ref: "#/components/schemas/EnvelopeError" }
        "422":
          description: Validation failed (missing/unknown role name)
          content:
            application/json:
              schema: { $ref: "#/components/schemas/EnvelopeError" }
```

## Binding Notes for Consuming Rooms

1. **Root keys are always fixed:** `success`, `data`, `error`, `meta` — none removed, none added.
2. **`error.fields`** = null except in `VALIDATION_FAILED`; its messages are detailed Arabic, and `message_en` is a generic English fallback.
3. **`permissions`** is a flat array of machine names (`users.create`), not objects — ready for direct interface gating.
4. On `error.code === "UNAUTHENTICATED"`: clear the session and redirect to login (a pattern binding on both rooms 06 and 07).

*Note: Arabic strings inside the fenced JSON blocks above are literal wire-format samples of the bilingual envelope (`message_ar` / localized payloads) and are preserved verbatim as contract data.*
