## 1. الهدف في سطر واحد

إعادة تنظيم كامل شيفرة SAKK بحيث يعيش كل منطق أعمال داخل سياقه المحدد بهيكل طبقي موحد، **بصفر فرق وظيفي** أمام المستخدم، وبقيود ثلاثة غير قابلة للنقاش: العقد المجمد `docs/api/openapi-v2.yaml` لا يُلمس · مخطط البيانات (migrations) لا يُغيَّر · منطق الدفع وKYC يُنقل فقط ولا يُعدَّل.

## 2. المكدس المقفول (قرار مالك — بلا نقاش)

| الطبقة | التقنية |
|---|---|
| خلفية | Laravel (الفعلي على القرص: PHP ^8.4 · Laravel ^12.0 — `backend/composer.json:12,14`) |
| ويب | React + Vite (admin · portal · site) |
| موبايل | Flutter/Dart |
| تنسيق | Tailwind CSS (v4 مثبت فعلاً في admin وportal عبر `@tailwindcss/vite`) |
| مؤثرات | Three.js — محصور بالموقع التعريفي وتصوير بياني اختياري، محظور في صفحات الدفع والدخول والتحقق |

ممنوع: Next.js · Vue · Angular · Node خلفي · GraphQL خادماً جديداً · أي مكتبة خارج هذه القائمة دون تسجيل قرار.

## 3. تدقيق الواقع — ما تحققت منه الخطة على القرص (أدلة ملف:مسار)

1. **الدومينات الاثنتا عشرة قائمة فعلاً** بهياكل داخلية متفاوتة: `app/Domains/{Agent,Card,Company,Compliance,Integration,Kyc,Partner,Support,System,Transaction,User,Wallet}` — بعضها كامل (DTOs/Enums/Mail/Policies/Console) وبعضها مجرد Models+Services.
2. **المنطق المهجر على الجذر مؤكد:** `app/Jobs/ProcessStripeIssuingWebhook.php` و`SendLoginAlertJob.php` · `app/Services/AdminNotificationService.php` · `app/Support/Money.php` · `app/Core/{Base/{BaseService,Controller},Http/ApiEnvelope,Traits/{ApiResponse,PhoneNormalizer}}` · `app/helpers.php`.
3. **اكتشاف مهم — نمط الـBC-Shim قائم:** `app/Services/KycService.php` مجرد غلاف فارغ `extends \App\Domains\Kyc\Services\KycService`. أي أن جزءاً من الهر سبق وأن حدث بنمط الأسماء البديلة. الخطة تعتمد هذا النمط أثناء النقل ثم تحذف الأغلفة في نهاية كل موجة بعد تحديث كل المراجع.
4. **مخالفة حدود موجودة فعلاً:** `Domains/Kyc/Services/KycService.php` يستورد `App\Domains\User\Models\User` و`App\Domains\User\Services\OtpService` مباشرة — يؤكد ضرورة فحص الاعتماديات الآلي من المرحلة 3 لا في النهاية.
5. **هيكل رباعي ناقص موجود في Transaction:** `Domains/Transaction/features/{application,domain,infrastructure,presentation}` بأحرف صغيرة وفيها `TransferAction.php` فقط — يجب توحيده مع الهيكل الرسمي الجديد وتوثيق انتقاله في جدول المطابقة.
6. **فجوة حرجة واحدة تكسر افتراض البرومبت:** **لا يوجد مجلد `tests/` ولا phpunit.xml في backend إطلاقاً** (رُوجعت قائمة جذر `backend/`). البرومبت يفترض «أساس اختبارات أخضر» — غير موجود. لذلك المرحلة 0 تتوسع لبناء شبكة الأمان قبل أي نقل (تفصيلها أدناه). هذا تعديل على ترتيب البرومبت وليس على أهدافه.
7. **واجهات الويب JSX بلا TypeScript** (`apps/admin/src` · `apps/portal/src` كلهما `.jsx`) مع Tailwind v4 مثبت في الاثنين وغير مثبت في `apps/site`. مجلد `src/design-system` مبكر موجود في admin.
8. **Flutter مهيأ مسبقاً:** `mobile/lib/{core,features,generated,l10n,shared}` — يوجد مجلد `generated` يرجح وجود توليد سابق؛ المحاذاة تبني عليه ولا تبدأ من الصفر.
9. **قيود التجميد موثقة رسمياً** في `projects/sakk/brain/CONTEXT.md:21`: لا تعديل وظيفي على الدفع/KYC · لا تغيير مخططي · OpenAPI المجمد لا يُمس. وقيم الهوية مصدرها `_core/core-spec.md` (العنابي ‎#7A1F2B · IBM Plex Sans Arabic · Lucide).
10. **تنبيه أسرار:** ملفات `.env` و`.env.production` موجودة في شجرة backend — فحص الأسرار في المرحلة 0 يجب أن يتحقق أنها خارج التتبع أو ينظفها فوراً.

## 4. الهيكل الرسمي المعتمد (كانون لكل دومين)

```
app/Domains/<Name>/
├── Domain/           # Models (كيانات المجال) · ValueObjects · Events · Exceptions · Interfaces (مستودعات وبوابات) · Domain-Services
├── Application/      # DTOs · Actions/Commands · Queries · Application-Services · Listeners · Jobs
├── Infrastructure/   # Eloquent-Repositories · Gateways الخارجية · Mail · Console-Commands · Casts
├── UI/               # Http/{Controllers,Requests,Resources,Middleware} · Routes/api.php
├── Database/         # Seeders فقط (migrations تبقى في database/migrations المركزية — لا تُلمس)
└── README.md         # عشرة أسطر: المسؤولية · الحدود · نقاط الدخول
```

**جدول مطابقة المواقع القائمة ← الطبقات (يلزم لكل نقل):**

| المجلد القائم | وجهته الرسمية |
|---|---|
| `Models/` | `Domain/` |
| `Enums/` · `Exceptions/` | `Domain/` |
| `Interfaces/` | `Domain/` (واجهات مستودعات/بوابات) |
| `DTOs/` | `Application/` |
| `Services/` | تُفرَّز: خدمات مجال → `Domain/` · منسقات حالة استخدام → `Application/` (الحكم: هل تلمس قاعدة عمل مالية أم تنسق فقط) |
| `Http/` (كل محتوياته) | `UI/Http/` |
| `Routes/api.php` | `UI/Routes/api.php` |
| `Mail/` | `Infrastructure/Mail/` |
| `Console/` | `Infrastructure/Console/` |
| `Policies/` | `Domain/Policies/` |
| `Casts/` | `Infrastructure/Casts/` |
| `Providers/` | يبقى باسمه (نقطة ربط الحاوية) |
| `features/*` (Transaction) | تُدمج في الطبقات الأربع أعلاه وتُحذف |

## 5. شجرة المراحل — تسع مراحل متسلسلة، لا قفز

> قاعدة الانتقال: لا مرحلة تبدأ قبل اجتياز تحقق سابقتها. كل التزام مستقل برسالة تذكر رقم المرحلة. الشجرة الرئيسية وحدها — لا فروع ولا worktrees.

### المرحلة 0 — الجرد وشبكة الأمان (توسعة إجبارية على البرومبت)
- [ ] تصدير قائمة المسارات الكاملة (`php artisan route:list`) إلى خط أساس `evidence/routes-baseline.txt`.
- [ ] بناء خريطة كل ملف مهجر على جذر app/ ← دومينه الهدف (تغذي جدول المطابقة الدائم).
- [ ] جرد علاقات Eloquent العابرة للدومينات (البداية: Kyc→User المؤكدة أعلاه).
- [ ] **بناء شبكة الاختبارات من الصفر** (الفجوة الحرجة): PHPUnit + phpunit.xml + اختبارات دخان (smoke) تغطي نقاط العقد الحرجة (auth · wallet · transaction · card · kyc) + التقاط **Golden Master** لاستجاباتها بصياغة قابلة للمقارنة الآلية + اختبار بصمة لقوالب البريد (تصيير ثابت المدخلات → hash).
- [ ] قياس خط الأساس: زمن استجابة P95 لعينة النقاط الحرجة · زمن بناء وحجم حزمة admin وportal.
- [ ] فحص أسرار (قبل) — يشمل التحقق من وضع ملفات `.env*` من التتبع.
- [ ] وسم التراجع `baseline-pre-ddd` على الشجرة الرئيسية.
- **تحقق:** اختبارات الشبكة خضراء (exit=0) · الوسم موجود · أرقام خط الأساس موثقة في `brain/evidence/ddd-restructure/`.

### المرحلة 1 — ورقة المعمارية (ورقية بالكامل، صفر كود)
- [ ] `docs/architecture/bounded-contexts.md`: السياقات الاثنا عشر · مسؤولية كل منها · نقاط دخوله العلنية.
- [ ] `docs/architecture/ubiquitous-language.md`: المسرد الملزم للتسميات الجديدة.
- [ ] `docs/architecture/mapping-legacy-to-ddd.md`: جدول «قديم ← جديد» لكل ملف سيُنقل — **صفر صف بلا وجهة** (تحقق آلي).
- [ ] قواعد الطبقات الأربع + مواصفة فحص الاعتماديات (أداة تفشل عند استيراد داخلي عابر للدومينات).
- **تحقق:** كل صف في جدول المطابقة له هدف صريح غير متقاطع.

### المرحلة 2 — النواة المشتركة
- [ ] تحويل `app/Core` → `app/SharedKernel` (BaseService · Controller · ApiEnvelope · ApiResponse · PhoneNormalizer · الاستثناءات العامة) — بلا أي قاعدة عمل خاصة بدومين.
- [ ] تحديث composer autoload · bootstrap/providers · إصلاح كل الاستيرادات · حذف `PhoneNormalizer` المكرر في favor النواة (يوجد نسخة في Core/Traits ونسخة في Transaction/Support — توحيد موقع واحد).
- **تحقق:** اختبارات خضراء · فرق المسارات صفر · `diff` نظيف.

### المرحلة 3 — موجة النقل الأولى (غير الحساسة): System · User · Support · Partner · Agent · Company
- [ ] دومين مستقل بكل التزام: هر المتحكمات/الخدمات/المهام من الجذر إلى الطبقات الأربع وفق جدول المطابقة · تسجيل ServiceProvider · تحديث مراجع الحاوية.
- [ ] مهام الجذر: `SendLoginAlertJob` → `User/Application/Jobs` · `ProcessStripeIssuingWebhook` → `Integration/Application/Jobs` (ينتظر موجته الحساسة إن لزم — يوثق مؤقتاً).
- [ ] `AdminNotificationService` → دومينها المستهدف · `Money.php` → `SharedKernel/ValueObjects` (عابر للدومينات بطبيعته).
- [ ] تشغيل فحص الاعتماديات بعد **كل** التزام (ليس نهاية الموجة).
- **تحقق لكل التزام:** فرق المسارات = 0 · اختبارات خضراء · فحص اعتماديات صفر مخالفة.

### المرحلة 4 — موجة النقل الثانية (الحساسة): Wallet · Transaction · Card · Kyc · Compliance · Integration
- [ ] نفس منهج الموجة الأولى + اشتراطان إضافيان:
- [ ] Golden Master: مقارنة استجابات كل نقاط هذه الدومينات قبل/بعد — تطابق دلالي كامل أو توقف الموجة فوراً.
- [ ] بصمات البريد: hash قوالب الستة عشر صنفاً متطابق قبل/بعد — أي اختلاف يلغي النقل ذا الصلة.
- [ ] معالجة خاصة: `Card/Services/Client.php` و`Integration/Services/Client.php` (عملاء Stripe/PayPal) تُنقل كما هي حرفياً إلى `Infrastructure/` خلف واجهات `Interfaces/` القائمة — طبقة العزل ACL تُفرض بالتوقيعات لا بإعادة كتابة.
- [ ] حذف أغلفة BC-Shim المتبقية بعد تحديث آخر مرجع.
- **تحقق:** diff = 0 على الالتقاط الذهبي · بصمات متطابقة · فرق مسارات صفر.

### المرحلة 5 — البنية التحتية والأحداث
- [ ] تنظيم `app/Infrastructure/{Payment,PaymentGateways}` كبوابات خارجية بعزل كامل — نوع حزم Stripe لا يتسرب لنماذج المجال.

- [ ] سلوكيات الجلسة والخطأ الموحدة: رسالة «تعذر إتمام الطلب…» + عودة ما بعد الدخول للمسار المقصود + إخفاء العناصر غير المصرح بها كلياً.
- [ ] مراجعة ثم تكرار المنهج ذاته على portal.
- **تحقق:** بناء ≤90ث · حزمة أولية ≤500KB مضغوطة · لقطات before/after متطابقة بصرياً لكل صفحة في `brain/evidence/ddd-restructure/screenshots/`.

## 6. القواعد الحاكمة أثناء التنفيذ (تُذكر في كل أمر عمل RCCF)

1. العقد المجمد ومخطط البيانات ومنطق الدفع/KYC: **نقل فقط** — أي diff عليهم = إيقاف فوري واستعادة.
2. كل التزام على الشجرة الرئيسية، مستقل، قابل للإرجاع منفرداً، برسالة `DDD-P<رقم المرحلة>: <وصف>`.
3. فرق المسارات + الاختبارات + فحص الاعتماديات بعد كل التزام — الثلاثة خضراء أو لا التالي.
4. لا تحسين مصاحب: أي إغراء إصلاح يُرى أثناء النقل يذهب لـ«ملاحظات مؤجلة» في التقرير.
5. كل اسم جديد من المسرد حرفياً · PSR-12 · README عشرة أسطر لكل دومين.
6. بيانات اختبار صناعية حصراً — ممنوع لمس بيانات عملاء حقيقية.
7. بروتوكول التعثر: «معطَّل بسبب X — الأثر Y — البديل Z» في صدر التقرير، والباقي يكمل.

## 7. المخاطر ونقاط التراجع (خلاصة تنفيذية)

| الخطر | الوقاية المضمنة في الخطة | التراجع |
|---|---|---|
| كسر دفع حي | تجميد صارم + Golden Master + موجة حساسة معزولة | وسم `baseline-pre-ddd` أو إرجاع التزام واحد |

| تضخم حزم Tailwind/Three.js | ميزانية 90ث/500KB + تحميل مؤجل + قياس بعد كل مرحلة واجهات | عزل حزمة المؤثرات وإرجاعها |
