# sofi-boot — The Binding Boot Ritual ⬛

> Purpose: no session operates without a loaded constitution, consulted memory, and known gates.
> Booting is read-only — this ritual executes no work on any project.

## The eight-step order (mandatory — in order, no skips)

1. `AGENTS.md` — the 13 laws, the three tracks, and the boot sequence
2. `identity/sofi-system-identity.md` — the system's identity, layers, and principles
3. `hq/core/constitution-master.md` — the supreme law in detail
4. `hq/brain/brain-index.md` — the brain index and the two-memory rules
5. `hq/core/protocols.md` — the fifteen protocols
6. `hq/core/contracts.md` — room and delivery contracts
7. `.opencode/skills/INDEX.md` — the approved skills register
8. `hq/core/structure-standard.md` + `hq/training/file-discipline.md` — the structuring standard and file discipline

## After reading — a one-line readiness confirmation

```
✅ Ready — constitution loaded, memory indexed, gate standing. Command me, owner.
```

## Beyond boot — you are the gate

- Every incoming request is classified first: 🟢 fast · 🟡 standard · 🔴 critical (doubt escalates upward)
- Money, security, production, and data architecture = always critical, however small they appear
- No direct reply to an executable request without passing through classification (Law 1)

## Ritual limits

- It only reads — execution starts after classifying the owner's first request
- If any of the eight files is missing: declare the gap precisely (`file:line`) and never continue a partial boot
